# 问数向导(data-guide-agent)迁移指南

> 把「引导式数据分析专家 + 数据查询技能」从一台机器搬到另一台机器的完整操作手册。
> 版本:2026-11-10 · 适用:macOS / Linux / Windows · 迁移包:`data-guide-agent-expert-20261110.zip`

---

## 一、五分钟速览

迁移就是三件事,做完就能用:

1. **解压 → 跑安装脚本**(Windows 用 `install.ps1`,mac/Linux 用 `install.sh`)
2. **确认数据库可达**(它是内网 PostgreSQL,不在公网)
3. **跑体检 → 试一条基准查询**(`26年9月银保APE` 应等于 **776.45 万元**)

三件事都过了,说明迁移成功;任一步失败,看第八节「常见坑」。

## 二、前置条件

| 项目 | 要求 | 怎么确认 |
|---|---|---|
| Python | 3.10 及以上 | `python3 -V` / `py -3 -V` |
| Python 包 | `psycopg[binary]`、`PyYAML` | 安装脚本会自动装 |
| 网络 | 能访问内网 PostgreSQL(真实地址见包内 `config.local.yaml`,此处不公开) | `nc -z <PG_HOST> 5432`(Windows:`tnc <PG_HOST> -Port 5432`) |
| 数据库账号 | 只读账号(由你提供) | 安装后填入 `config.local.yaml`(模板见 `config.local.example.yaml`) |
| 磁盘 | ≥ 50 MB(含 Chart.js 离线资产) | — |
| WorkBuddy | 已安装并至少启动过一次(会生成 `~/.workbuddy`) | 见第三节「家目录」 |

> **不需要**:Node.js、npm、浏览器插件、外网访问。图表库 Chart.js 已离线内嵌。
> **不需要**:数据库写权限。技能只执行 `SELECT`。

## 三、安装位置(先搞清路径)

包里的东西要落到**两个位置**,少一个都不行:

| 内容 | 作用 | macOS / Linux | Windows |
|---|---|---|---|
| 专家包 | 人设、对话节奏、口径红线 | `~/.workbuddy/plugins/marketplaces/my-experts/plugins/data-guide-agent/` | `%USERPROFILE%\.workbuddy\plugins\marketplaces\my-experts\plugins\data-guide-agent\` |
| 技能 | 真正取数与出报告 | `~/.workbuddy/skills/data-guide-agent/` | `%USERPROFILE%\.workbuddy\skills\data-guide-agent\` |

- 只放**技能**:能查数,但没有「问数向导」的引导节奏与口径纪律
- 只放**专家**:人设能唤起,但一取数就找不到脚本

Windows 家目录通常就是 `C:\Users\<你的用户名>\.workbuddy`。如果你的 WorkBuddy 装在别处,把 `install.ps1` 顶部的 `$PluginDst` / `$SkillDst` 两个变量改掉即可。

## 五、迁移步骤 · Windows

### 第 1 步:解压

把 `data-guide-agent-expert-20261110.zip` 解压到任意目录(建议 `D:\tools\`),**不要在压缩包里直接运行**。

### 第 2 步:先空跑一遍(推荐)

在该目录按住 `Shift` + 右键 →「在此处打开 PowerShell 窗口」,然后:

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 -DryRun
```

它只打印要做什么,不落盘。确认目标路径看着对(尤其 `.workbuddy` 的位置)。

> `-ExecutionPolicy Bypass` 是绕过脚本签名策略的临时开关,只对本次执行有效,不改系统设置。

### 第 3 步:正式安装

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

脚本会依次输出 5 段进度:

| 阶段 | 做什么 | 看到什么算过 |
|---|---|---|
| 1/5 检查源文件 | 确认包完整 | `OK 源文件齐全` |
| 2/5 备份旧版本 | 已有旧版则改名 `*.bak-<时间戳>` | 有备份提示,或跳过 |
| 3/5 安装 | 复制到插件目录与技能目录 | 打印两个目标路径 |
| 4/5 依赖 | 检查/安装 psycopg、pyyaml | `OK psycopg / pyyaml 已就绪` |
| 5/5 体检 | 跑 `doctor.py` | 六项全部绿色 |

### 第 4 步:设编码(重要)

Windows 控制台默认 GBK,输出中文和 ✅ 会报 `UnicodeEncodeError`。安装脚本已临时设置,但**以后手动跑脚本前仍要设**:

```powershell
$env:PYTHONUTF8 = "1"
setx PYTHONUTF8 1        # 永久生效,重开终端后不用再设
```

### 第 5 步:试一条基准查询

```powershell
cd $env:USERPROFILE\.workbuddy\skills\data-guide-agent
$env:PYTHONUTF8 = "1"
py -3 scripts\query.py --intent single --metric ape --period 2026-09 --channel 银保
```

**期望输出:`APE:776.45 万元`**。数字对上,迁移即成功。

## 七、数据库配置(迁移最容易卡的一步)

技能连的是内网 PostgreSQL(库名见 `config.local.yaml`,表 `policy_detail`,约 72 万行)。配置优先级:**环境变量 > `config.local.yaml` > `config.yaml`**。

### 情形 A:同一内网 / Tailscale 可达

什么都不用改,直接能用。先用这条确认端口通:

```bash
# <PG_HOST> 换成包内 config.local.yaml 里的真实地址
nc -z <PG_HOST> 5432 && echo "通" || echo "不通"
```

### 情形 B:地址不同

改 `~/.workbuddy/skills/data-guide-agent/config.local.yaml`(Windows 同理):

```yaml
datasource:
  host: "<PG_HOST>"          # 真实内网地址
  name: "<DB_NAME>"          # 真实库名
  user: "<READONLY_USER>"    # 只读账号
  password: "<DB_PASSWORD>"
```

### 情形 C:不想改文件,用环境变量覆盖

```bash
export DGA_DB_HOST=<PG_HOST>
export DGA_DB_PORT=5432
export DGA_DB_NAME=<DB_NAME>
export DGA_DB_USER=<READONLY_USER>
export DGA_DB_PASSWORD=***
```

Windows PowerShell:

```powershell
$env:DGA_DB_HOST="10.0.0.5"; $env:DGA_DB_PASSWORD="***"
```

其余可用环境变量:`DGA_DB_TYPE`、`DGA_TABLE`、`DGA_OUTPUT_DIR`、`DGA_PROACTIVE_MENU`。

### 情形 D:完全没有数据库,只想先看效果

直接双击 `samples/参考产出_银保APE经营分析报告.html`,这是真实产出样例。技能本身要等数据库通了才能查数。

## 九、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `No module named 'yaml'` | 依赖装到了别的 Python | 用装了依赖的那个解释器,或建 venv(见第六节) |
| `UnicodeEncodeError` / 中文乱码(Windows) | 控制台 GBK | `$env:PYTHONUTF8="1"`,永久:`setx PYTHONUTF8 1` |
| PowerShell 报「无法加载文件,未经数字签名」 | 执行策略限制 | 用 `powershell -ExecutionPolicy Bypass -File install.ps1` |
| `doctor.py` 报数据库不可达 | 内网/Tailscale 未通,或口令过期 | 先 `nc -z host 5432`;再看 `config.local.yaml` |
| 报 `Address already in use` | 8899 端口已被占用(预览服务) | 直接复用同一端口;或 `serve_output.py --port 8900` |
| 档案「从第 1 节重新开始」 | 没在技能目录下执行,产物落到了别处的 `./output` | **必须先 `cd` 进技能目录**再跑脚本 |
| 预览面板看不到更新 | 浏览器缓存了旧页面 | URL 加 `?v=<时间戳>` 破缓存,或 Ctrl+F5 / ⌘R 硬刷新 |
| 报告章节串位 | `final_report.py` 按标题关键词匹配骨架,标题含「缴费」会被「产品线定位」抢走 | 改档案节标题措辞后重建报告 |

## 十、安全与合规(转发前必看)

1. **`config.local.yaml` 含明文口令和内网地址**。只给自己换机 → 可原样带;要发给同事 → **先把 `password` 清空**,或整份删掉只留 `config.yaml`,让对方自己填。
2. **数据是脱敏保单明细**,产品名是代号(如 `Product_XXX`)、机构名是代号(如 `Branch_01`)。产物 HTML 里同样只有代号,**不要**试图反推真实名称再入库。
3. **只读账号**:技能全部是 `SELECT`,不要在生产库上换成写账号。
4. **产物目录会越积越大**:`output/` 里是历史档案与 session 状态,迁移包里已剔除,新机器从空开始。不需要历史档案就别拷。
5. 内网地址、口令不要写进 `config.yaml`(该文件会进 git),一律放 `config.local.yaml` 或环境变量。

## 十一、回滚

安装脚本在覆盖前会把旧版改名为 `data-guide-agent.bak-<时间戳>`,回滚就是把名字改回来:

**Windows**

```powershell
$base = "$env:USERPROFILE\.workbuddy\plugins\marketplaces\my-experts\plugins"
Rename-Item "$base\data-guide-agent" "$base\data-guide-agent.new"
Rename-Item "$base\data-guide-agent.bak-20261110-150000" "$base\data-guide-agent"
# 技能目录同理,把路径换成 ...\.workbuddy\skills\
```

**macOS / Linux**

```bash
cd ~/.workbuddy/skills
mv data-guide-agent data-guide-agent.new
mv data-guide-agent.bak-20261110-150000 data-guide-agent
```

> 本机(macOS)同步版本时额外做了一份备份:
> `~/.workbuddy/skills/.backups/data-guide-agent-live-<时间戳>.tar.gz`

## 十二、迁移后第一次对话怎么验

装好后在 WorkBuddy 里唤起「问数向导」,按下面三句走一遍,能对齐就说明人设和技能都在:

1. 「**菜单**」→ 应列出 9 个指标、按主题包分组
2. 「**26年9月银保APE**」→ 应直接给数(776.45 万元),并在聊天里出表、**不生成 HTML**(快查规则)
3. 「**帮我做分析报告**」→ 应切换到 6 节模板模式,逐节确认,产出档案与报告两份 HTML

第 2 条尤其关键:新版技能规定「仅问数快查只出数、不落 HTML、不开档案」,如果它还在生成 HTML 文件,说明装的是旧版。
